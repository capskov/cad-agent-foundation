## 九、本轮新增：保存/发布边界收口 + 恢复回归（2026-11-17）

### 9.1 安全缺口修复：不再有"不完整方案 B"

`client/foundation.py` 的 `apply_with_optional_save()` 原先在 save 回执出现后直接改写 `session['drawing']`，但此时写入的最终 finalize、插件 journal scope、服务端固定图纸身份都没有迁移，属于半成品方案 B。

现在的规则：

- `apply --save-to` **只接受**当前绑定 owned DWG（`require(target==owned, ...)`），其他路径在**任何 save 执行前**即拒绝，错误信息直接指向 `publish-dwg`。
  实测：`--save-to ...\deliverables\wrong.dwg` → `apply --save-to must target the bound owned drawing: ...\drawings\work.dwg (use publish-dwg for a delivery copy, got ...)`，且 `wrong.dwg` **未生成**。
- 回执 `saved_path` 与绑定路径不一致时 → `persisted=False` + `next_action=save_target_differs_from_bound_drawing`，身份不动。
- 完整方案 B（`switch-revision`）**仍未实现**，边界保留：只在确需"新路径 DWG 成为活动工作图"时开发，且要 session / 插件 journal scope / 服务端绑定三者原子一致。

### 9.2 新功能 `publish-dwg`：交付副本

语义是"发布已完成保存、校验可信的当前工作 DWG"，纯客户端文件操作，**不改变** CAD 活动文档、`session['drawing']`、journal scope、revision。

实现要点：

1. 目标必须是 `.dwg`、不含 `..`、≠ 绑定工作图；已存在默认拒绝，需 `--overwrite`。
2. 发布前重新 `dwg_bind_active_document` 取**实时**文档状态并校验绑定身份（绑定时刻的快照会残留旧 `dbmod`，这是本轮实测踩到的坑）；要求 `document_count==1`、`command_active==0`、加载插件 MVID 与 session 一致、**native/server 两端 fence 均为 0**。
3. **闸门改为"上次已验证保存的摘要"，不再用 DBMOD**：API 级 `SaveAs` 之后 DBMOD 仍为 1，用它当闸门会永远拒绝发布。`persist()` 成功时把 `last_saved_sha256 / last_saved_at_utc / last_saved_request_id` 写回 session（不涉及任何路径/身份变更），发布要求磁盘当前摘要 == 该摘要。
4. 复制到目标目录内的唯一临时文件 → SHA256 比对 → `os.replace` 原子替换 → 复核目标摘要；任一步失败都不留"貌似完整"的交付 DWG。
5. 探测 `xref_definitions`，有外部引用则 `warning` + `complete_engineering_package=false`（单 DWG 不等于完整工程包）。
6. 每次发布写 `publishes/<UTC 时间戳>-<stem>.json`：源/目标 SHA256、字节数、时间、`overwriting`、`drawing_identity_changed:false`、`journal_scope_changed:false`、`external_references`。

### 9.3 `save` 语义收敛

独立 `save` 现在只有一个含义：把当前绑定 DWG 写回它自己的文件（`persist(session['drawing'], overwrite=True)`）。它**不是**发布，也不做任何路径决策；随后遍历 `requests/*.json` 逐个 `query`（只查不重放），输出 `pending_write_requests` 与 `drawing_identity_changed:false`。另新增只读审计入口 `status`（可带 `--request-id`）。

| 第二次写入 | `rejected_before_submission`（`fence conflicts with an existing operation`），**未**产生新行 |
| 原请求审计 | `status --request-id rec-1` 返回完整记录：`phase=completed`、`effects=committed`、`verification=passed`、`pending=true`、`write_fence_released=false`、`plugin_sequence=4` |
| `stop` | 正确拒绝：`Unresolved write fence: {'native': 1, 'server': 1}` |
| 显式 `save` | `completed`，`pending_write_requests=[]`，插件 journal 行数仍为 **1**（无重放） |
| 收尾 | `stop` 成功，`fences {0,0}` |

**必须如实记录**：本包**没有** `resolve --inspect/--recover/--discard`，服务端工具面只有 `dwg_job_get` / `dwg_job_cancel`。因此"已提交但验证失败"的恢复路径**未实现**，本轮只交付最小安全闭环：可查询原请求、绝不重放、fence 保持、持久化后释放。完整恢复路径需单独立项（要求：磁盘/句柄/哈希/账本证据一致才可恢复，不得直接宣布成功）。
