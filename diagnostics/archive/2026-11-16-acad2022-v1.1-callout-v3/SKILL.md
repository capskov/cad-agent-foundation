# CAD 引线标注排版（LEADER + MTEXT）

本 Skill 只管**引线几何和文字关系**。内容、锚点身份、图层/样式仍按项目数据；不要用本 Skill 伪造锚点或改底图。

## 1. 强制几何契约

一条合格的 callout 由三个点组成：

- **A**：锚点，落在被标注对象上，带圆点。
- **B**：折点，位于文字靠近锚点的那条边外侧（文字前），并与文字底边同高。
- **C**：文字底边的远角，和 B 同一水平线。

规则：

1. **A→B 必须是斜线。推荐 30°～80°，常用 35°～45°，优先 45°（“90+45”）；空间紧时可用 60°、75°、80°（“90+75”一类）。** 这是推荐区间，不是单一固化角度；按版面避让选，但严禁接近水平。
2. **折点 B 的内角（B→A 与 B→C 的夹角）必须是钝角，>90°。** 因为 B→C 水平，内角 = 180° - 斜线仰角；45° 斜线对应 135°，75° 对应 105°，80° 对应 100°。**禁止折成锐角。**
3. **同组/同侧的 callout 尽量保持平行、角度统一**（例如都用 45°），局部避让才换角度，并在计划里记录理由。
4. **找不到位置时可以退化为 180° 直线（A、B、C 共线），但必须显式标记 `leader_straight=true`，不能把直线伪装成正常斜线。** 这是最后手段，不是默认；即使退化，也不能出现锐角折点。
5. **B 在文字前面**，C 在文字另一侧底角；B→C 从文字底边通过，把文字“托住/包住”。线段不得穿过文字，不得停在文字边缘外。
6. **文字整体必须始终在横线之上**，单行；水平段长度等于文字实际宽度（加少量 clearance），不是文字右侧的一小段。文字一旦落到横线下方或与横线相交，直接判失败。
   - **SHX 字体下探修正**：`hztxt_e.shx + hztxt.shx` 在 AutoCAD 2022 中，MText 的 `extents.min.y` 可能落在基线上，而汉字字形还会向下探出；此时 `y=C.y` 的横线会切到字脚。只在这种情况下允许把横线整体下移 `text_gap`（本图实测 `0.012`，上限 `0.02`）：文字插入点 `position=(C.x, C.y+text_gap)`，`annotation_offset=(0,-text_gap)`，横线仍是 `C.y`。这是字体下探补偿，不是排版避让；默认 `text_gap=0`，不得用更大的负 offset 掩盖引线/文字布局错误。读回必须满足 `MTEXT.extents.min.y - leader.C.y = text_gap`，并在 PDF 放大图上确认横线在字下方而不是切字。
7. **annotation_offset 必须为 (0,0)**。C 就是文字插入点，不允许再用 `(0.02,-0.02)` 把线压到文字下方 20 mm。
8. 文字宽度必须足够单行显示；宁可加宽文字框，也不允许折行。中文按 `1.0×字高`、ASCII 按 `0.55×字高` 估算，再乘 1.35 安全系数。

## 2. 左右两种排法

### 文字在锚点左侧（最常用）

```text
                 A (锚点/圆点)
                /
               /  θ 30°–80°，优先 45°
              B
   [ 单行文字，整体在横线之上 ]
C──────────────────────────B
↑文字底边                    ↑文字底边
```

- `B = (A.x - run, A.y ± run*tanθ)`
- `C = (B.x - width, B.y)`
- `attachment = BottomLeft`，`position = C`
- `annotation_offset = (0,0)`
- 文字底边 = B/C 的 y，文字只能向上长，不能落到横线下面。

### 文字在锚点右侧（镜像）

```text
A (锚点/圆点)
 \
  \  θ 30°–80°，优先 45°
   B
   [ 单行文字，整体在横线之上 ]
   B──────────────────────────C
   ↑文字底边                    ↑文字底边
```

- `B = (A.x + run, A.y ± run*tanθ)`
- `C = (B.x + width, B.y)`
- `attachment = BottomRight`，`position = C`
- `annotation_offset = (0,0)`
- 右排也一样：文字在横线之上，横线只托底。

`run` 由高差反算：`run = |Δy| / tanθ`。先定文字底边高度，再算 B 的 x；不要先画一条长横线再硬接斜线。

## 3. 多组布局判断（同侧顺序 / 平行带 / 交叉检查）

单组几何正确，不等于整组布局正确。多组同侧标注先做布局判断，再落图。

1. **先读锚点顺序，再排文字行。** 同侧、同开口时，按锚点沿对象方向（通常是竖向 Y）排序，文字行保持同一顺序：低锚点对应低文字行，高锚点对应高文字行。左开口、右开口都按这个关系；右开口时右下锚点保持右下关系。锚点顺序和文字行顺序反过来，斜线必然交叉。
2. **优先平行带。** 同侧多组尽量用同一角度、同一斜率，并把 B 点放在同一条竖向基准线（或同一水平基准投影）上；文字行按顺序递增。这样得到的是平行带，不是一组各自为政的斜线。
3. **用投影排序，不要直接比较折点 x。** 同开口的组先投影到共同的水平/竖向基准，再比较先后；曲路、混合开口和大面积跨中线目标要结合真实图面判断，不能把世界 Y 正负直接当道路侧。
4. **交叉检查必须覆盖相邻组。** 同一侧、相邻区域、固定的旧组一起检查：引线-引线交叉、引线穿到别组文字、文字框重叠、引线压到尺寸线/图框。分组分别计算没有冲突，不代表整片区域没有冲突。
5. **密集处的合法排法**：阶梯、平行带、有序扇形；左右开口分流；同组不必严格等角、等长、等间距，“清楚、可追踪”优先于“引线最短”。
6. **发现交叉的处理顺序**：先换文字行/顺序，再换开口方向，再换角度（45°→60°/75°/80°），最后才用 180° 共线退路。不能靠压盖文字、加长引线或负 `annotation_offset` 掩盖交叉。
7. 本次围墙实例：`co-concrete` 锚点 y=0.45、`co-ground` 锚点 y=0.62；旧文字行分别为 1.00 / 0.27，锚点高的反而文字低，两条 45° 线交叉。修正为 `co-concrete` y=0.86、`co-ground` y=1.03，B.x 统一 2.79，六条 45° 线同斜率，文字行与锚点顺序一致，交叉消失。

## 4. 角度参考

角度是推荐，不是固定值。常用 35°～45°；空间窄、需要靠近锚点时，可以做到 60°、75°、80°。

| 角度 | tanθ | 高差 0.35 | 高差 0.50 | 高差 0.70 |
| --- | --- | --- | --- | --- |
| 30° | 0.577 | run 0.606 | 0.866 | 1.212 |
| 35° | 0.700 | run 0.500 | 0.714 | 1.000 |
| 45° | 1.000 | run 0.350 | 0.500 | 0.700 |
| 60° | 1.732 | run 0.202 | 0.289 | 0.404 |
| 75° | 3.732 | run 0.094 | 0.134 | 0.188 |
| 80° | 5.671 | run 0.062 | 0.088 | 0.123 |

同一张图优先保持相近角度（例如都用 35° 或都用 45°）；60°～80°用于局部避让，并在计划里记录理由。

## 5. AutoCAD 2022 的落地字段

`callout` 计划步骤使用：

| 字段 | 要求 |
| --- | --- |
| `text` | 单行；不手动插入换行 |
| `position` | 等于 C（文字底边远角） |
| `height` | 字高 |
| `width` | 按第 1 节公式，宁可偏宽 |
| `vertices` | `[A, B, C]` |
| `dot_radius` | 按项目样式，通常 0.0125 |
| `attachment` | 左排 `BottomLeft`，右排 `BottomRight` |
| `annotation_offset` | `[0,0]` |
| `dimtad` / `gap` | 0 |
| `has_hook_line` | false |

2022 不需要为这个几何规则改 C# 插件；`callout` 已支持 vertices、attachment 和 annotation_offset。改的是计划生成器和验收，不是底层写入器。

## 6. 执行顺序

1. 量文字：按实际字高/字数算宽度，必要时加宽 10%。
2. 定文字底边高度：避开相邻标注、图框、标题栏、尺寸线。
3. 多组先排布局：按锚点顺序定文字行，同侧优先同一角度/同一 B.x 的平行带；检查引线-引线、引线-别组文字、文字框重叠。
4. 按选定角度（优先 45°；需要时 60°/75°/80°）反算 B；确认 B 在文字前、C 在文字远角。
5. 生成 `[A,B,C]` 与 `position=C`、`annotation_offset=[0,0]`；文字必须整体位于 B–C 横线之上。
6. 在图纸副本上 apply；读回 Leader 三个顶点、MTEXT 插入点、attachment 和文字框，确认文字框底边不低于横线。
7. 出 PDF/渲染，目视确认：斜线明显、水平段贴文字底、文字整体在横线之上被托住、没有折行、同侧没有交叉。

## 7. 禁止项

- 3°～5°接近水平的引线。
- B 在 C 右侧（水平段跑到文字外面）。
- C 比文字底边低 0.02（线不贴文字）。
- 水平段只到文字右边缘，文字左半部分悬空。
- 文字折行后用“两行也正常”解释。
- 用 `annotation_offset` 的负 y 值掩盖几何错误；唯一例外是 hztxt_e 字体下探 ≤0.02 的补偿，且必须有 `text_gap` 读回和放大图证据。

## 8. 验收清单

- [ ] A→B 角度在 30°～80°，常用 35°～45°，且目视明显倾斜。
- [ ] B→C 水平，y 与文字底边一致；**文字整体在横线之上**。
- [ ] B 在文字前，C 在文字远底角，水平段覆盖整个文字实际宽度。
- [ ] 同组引线角度统一/接近平行。
- [ ] 同侧文字行顺序与锚点顺序一致；平行带内没有引线-引线交叉、引线穿别组文字、文字框重叠。
- [ ] `annotation_offset=(0,0)`，C=position。
- [ ] 文字单行，宽度足够。
- [ ] 读回顶点与计划一致；PDF 目视通过。字体下探间隙时，`MTEXT.min.y - C.y = text_gap`，横线不切字。

几何核对可直接运行 `scripts/validate_callouts.py plan.json`；多组布局再运行 `scripts/validate_layout.py plan.json`，检查引线交叉、引线穿别组文字、文字框重叠、同侧锚点/文字行顺序。两个脚本都只检查几何，不替代 CAD 读回和目视。
