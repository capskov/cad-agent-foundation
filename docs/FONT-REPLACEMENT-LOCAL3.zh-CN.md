# 字体替换：本地 1.2.0-local.3

字体选择、粗分类及看图调整由 cad-font-diagnostics 与项目资料库负责。用户/任务/技能指定优先；没有选择时先提出候选并询问。字高和长度均须看图大致合适，不以改字体名称等同排版验收；不要求拟合算法。字体信息和几何读回不证明所有字符能显示。

## 两个原生操作

仍通过 `dwg_apply_plan`，保留图纸身份、事务、旧值摘要、单次提交及写入围栏。

`set_text_style_font`：参数 `id,op,name,expected_sha256,font_file,big_font_file`。摘要为绑定目录 `text_styles[name]` 的规范JSON SHA256，读取后应新鲜使用。目标必须是已有本地文字样式，不能是外参或形状库；本轮目标字体限SHX文件名，大字体可空；CAD搜索路径中必须能找到文件。来源样式可以是TTF或SHX。保留样式名称、字宽、固定字高及竖排设置；显式影响该样式的所有引用，包括块、布局及尺寸引用。不会清除多行文字内嵌字体，不设置全局FONTALT/FMP，不下载字体。

换字体后在同一事务重新排版引用样式的本地MText，保持其原Contents和Location，避免内存缓存沿用旧字体宽高、保存后才变化。扫描上限100000个本地块成员，超限回滚。字体对的可用性不等于字符集、专用符号或任意字体组合已通过验证。

`set_text_metrics`：参数 `id,op,targets,height_scale,width_scale`。targets每项为`handle,expected_sha256`，每步1～32项，全计划仍至多64个对象。两个倍率均0.01～100，1表示不变；width_scale乘实体WidthFactor，height_scale乘Height。保留内容、样式、旋转及对齐方式；基线左对齐保留Position，其他支持的对齐保留AlignmentPoint并调用原生对齐更新。支持二维WCS、零厚、模型空间独立DBText，拒绝Fit/Align、属性文字及带持久反应器对象。不是MText行宽或内嵌字宽修改。

DBText读取新增`width_factor`，非基线左对齐另读`alignment_point`。实际字长由Agent看图判断；不会自动采用芦求路的1.375倍率。

## 芦求路经验的归属

用户已认可的图纸采用hztxt_e+hztxt，正文保留原字高字宽，HT类实体宽度0.8→1.1。这个工程选择记录在项目字体资料库，不作为底座所有TTF替换的默认倍率。底座只增加实现该选择需要的通用能力。已放行DWG不再修改。

## 验证与剩余边界

验收记录及限定实机证据见项目《智能底座字体替换升级交接_20261016.md》。离线契约检查不代替CAD实机、保存读回或看图。

本轮不提供自动全图字符审计、缺字定位、自动下载、TTF目标族选择、内嵌字体批改、属性字宽、特殊符号兼容证明。Windows字体目录存在某文件，也不证明CAD当前能按文件名搜索到它。后续按实战反馈补。
