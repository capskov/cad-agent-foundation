# v1.2.0-beta.1 实图收尾与发布准备

2026-10-16。沿用第一阶段已实测的AutoCAD2026插件，MVID `7ef04b37-2f1a-485d-8a0e-2eb8ab319281`。本阶段未改执行代码、未扩展接口，未提交或发布GitHub。只读几何接口与现有普通实体绘制能力组合使用，没有加入专业道路Skill或自动拼接算法。

用户在本阶段进一步明确按类型抽样，代表对象通过就停止扩查。给水代理清单在该补充前已完成读取；之后图面及重开核验只选直线、多段线、圆、圆弧连接和布局框代表样本。没有宣称每个对象均获图面验收。运行回执自身的必要执行读回与Agent额外验收分别记录。

## 道路样图A：提取几何可以重建和使用

复用已提取的10个可读代理几何，在自有副本原位重建成130条普通轻量多段线，表达原返回的4416个基础图元。连续直线仅按原生顺序分组，圆弧保留bulge；因已有单条128顶点上限分段，不拟合或改变曲线。另29个不可读代理不作转换。源代理保留，便于对照，没有真正炸开或擦除。

其中三条中线的464段重建为5条普通多段线。Agent对一条5段路径计算向左偏移2个原始单位，并沿返回路径起点累计50个原始单位设置圆形标记；另调用既有原生直线offset操作。两者均通过底座MCP落图。这里的累计距离不等于专业软件桩号解析；全路径偏移是本样例的Agent显式计算，不是新增通用道路偏移算法。

CAD2026界面抽查直线、半径15的圆弧及连接处：普通实体与原中线叠合，偏移线保持可见间距，圆形定位标记落在路径上。道路图保存通过、保护释放，重开后抽查普通多段线和定位圆仍可读取。其他重建线层可切换显示，验证图仍保留原代理和原标注，不能称作清除了全部代理的纯原生图。

## 给水样图B：不同代理类型

模型空间读取168个代理、24个原始类名（`CCivilDb…`），71个完整返回、34个部分返回、63个无可用几何。105个有几何的对象共返回1063条直线、16个圆、1393条多段线、24段圆弧；部分状态包含跳过文字。主管、节点、纵断节点/主管、地面线、纵断图网格和部分表格都能返回显示几何。部分标注、编组及空显示对象不可用，不继续解析私有格式。

实际抽查两段给水主管和一个节点，生成6个普通实体并在CAD界面原位叠合；端点、圆心、半径读回一致，图面位置/轮廓一致。源主管多段线宽度0.24已读到，但既有polyline创建接口不支持逐顶点宽度，本次重建是零宽中心线/轮廓验证，未宣称宽度、线型、文字样式全部还原。真实普通样条也取得控制点、节点和权重；未将其继续转为新样条，也未把它算成代理内样条实测。

TIN类对象仅取得66条显示线，不表示恢复了TIN拓扑或高程。全部输出仍是显示几何，不能以类名或画面相似保证原专业设计数据的精度和完整性。

## 实际图框和分图内框

在CAD布局界面抽选一个裁剪分图内框，由原生LIST取得句柄后交给底座MCP读取。它是普通多段线，5顶点、首尾点重复，`is_closed=false`但坐标路径闭合；宽370、高252.164，完整顶点已取回。这里是图纸空间坐标，不能与模型道路坐标直接混用。

关联Viewport可读现有属性和外包范围，通用Explode返回eNotApplicable；本阶段不增加视口专用几何接口。模型空间候选查询不会列出纸空间对象，因此使用CAD界面找到样本句柄，读取和几何返回仍通过MCP；没有把界面选取称作MCP全布局检索。

正式图框是缺失的外部参照。CAD显示路径占位文字，读取只得到文字跳过项，不能取得实际外框边界。没有强行以占位包围盒冒充真实图框，也没有替换外参。该样本的正式外框验证受源文件缺失限制。

## 保存核验的独立限制：保留保护

给水副本的6个实体已写入，后续原生保存也确已落盘、DBMOD=0，但独立磁盘数据库读回后部分文字样式的font_file被AutoCAD归一化，触发严格全图符号表核验失败。回执中选定几何、图层、布局和模型对象集合一致，text_styles有差异；不能据此宣称整图保存完全通过。

原始保存请求保持`committed / verification failed`，原生及服务端保护各1。没有重复提交保存、更换提供者绕过、手工清除栅栏或强关该会话。磁盘文件是待确认的诊断副本，不是验收通过的正式成果。这是该旧图字体/保存兼容性限制，未通过字体替换或放宽核验处理；进一步处理另列事项。

道路图曾尝试将代理作为保存核验目标，被`save_entity_changed`拒绝，确认无写入后改用普通原生实体作为新保存计划的核验目标，保存成功。这不证明代理摘要可用作稳定的编辑/保存前置条件；当前代理支持范围仍为读取，代理源对象编辑不在本次支持范围。
