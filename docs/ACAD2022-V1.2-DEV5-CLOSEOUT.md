## 暴露并修复的底座缺陷

### 1. CLI 没有“列图层”动作（已修）
按图层认线是本次关键，但 CLI 只有 `query`（需过滤参数），没有直接列全部图层的入口。
- `client/foundation.py`：新增 `layers` 动作，调用 `dwg_list_layers`。
- 实测列出 102 个图层，直接定位 `…$0$0车辆段`、`…$0$0瓦窑村排水沟保护范围`、`管理范围面` 等。

### 2. 多段线/计划点数硬上限挡住加密与外包络（已修，服务端+插件双端）
旧上限：单条多段线 **128** 点、整单 **1024** 点、语义 **128 KiB**。瓦窑沟 2m 加密 1392 点、地铁外包络 1895 点全部被拒。
- `shared/Execution/FoundationDrawingPlan.cs`：单线/闭合边界上限 128 → **20000**；整单顶点 1024 → **50000**；语义字节 131072 → **8388608（8 MiB）**。
- `shared/Execution/FoundationPhase2.cs`：`set_open_polyline` 上限 128 → 20000。
- **关键教训**：只重编服务端不够。插件端 `FoundationPlanWriteHandler` 用同一份 `FoundationDrawingPlan.IsCanonicalValid/Parse` 做二次校验，旧插件 DLL 仍带 128 上限，导致请求在服务端预留后到插件被静默拒收，回执 `unknown / the plugin has no authoritative snapshot`。必须**同时重编 2022 插件**（`plugin-acad22`，net48，引用本机 AutoCAD 2022 托管程序集）。
- 重编后插件 MVID `9092b51b-226e-46ca-881c-b861805d9d68`，SHA256 `E67680845F220E3E8149302D4569C32BE01754F6A29F5A8D53E6E1B78DD07E81`，bundle `8DF07BE01DB7C53DE69943958E4243B452ED6E3CC3F749DD32152A8F27E54C80`。
- 实测：1392 / 1895 / 17 点三条均 `committed_verified`。

### 3. 大输出回读被客户端截断（记录，未改）
`read` 三条大线（含 geometry）共 329 KB，超客户端序列化上限，`data` 变为 `{truncated, preview, hint}`。
- 绕法：用写入回执 `result_json.after[handle]` 核验 `is_closed/vertex_count/area/layer`；或逐条小批量 `read`。
- 本轮以回执核验：三条 `is_closed=true`，点数 1392/1895/17，面积 75397.1/129673.2/18090.5。

## 仍未解决 / 需注意

1. `geometry_offset` 硬上限 **4096**：整段一次读不完（`geometry_offset requires ... integer 0..4096`）。本轮用**分段空间窗口**采集（南/中/北三段，段间重叠）绕开；未抬高该上限。
2. 分页读取中途偶发 `drawing_path_mismatch`（dev5a 会话），原因未定位；重开新工作区恢复。
3. `resolve --discard` 仍被 `BIMWRIGHT_RC_UNVERIFIED_DISCARD` 门控，真实图纸不可用；未知写只能靠新工作区规避。
4. `install` 会在工作区留下会话记录，同工作区再 `start` 报 `Existing session preserved`；**start 必须用全新工作区**。
5. 非均匀缩放块内 `Circle/Arc` 变换仍可能跳过（dev4 遗留）。
6. 包未签名；Plugins 目录历史版本继续累积。
