# ACAD2022 V1.2-dev6 收口记录

对象：`releases\ACAD2022-V1.2-dev6\runtime`（manifest version `ACAD2022-V1.2-dev6`）
基线：dev5（`ACAD2022-V1.2-dev5`）+ 本记录三项修复。
宿主：AutoCAD 2022（`F:\Program Files\Autodesk\AutoCAD 2022`），插件 net48，服务端 net8。

## 一、本次已修（已编译、已实测）

1. `geometry_offset` 上限 4096 → 1,000,000
   - 位置：`shared/Cad/HandleBatchRequest.cs`（校验）、`server/Tools/QueryTools.cs`（schema 描述）。
   - 原因：页大小固定 64，大块翻到第 64 页即 offset≈4096 被拒，31 页以上的块读不完。
   - 实测：`read --handles 13365A --geometry-offset 5000` 返回 `offset=5000, primitives=[], has_more=false`，不再报 `0..4096`。

2. 每实体 `issues` 上限 128 → 1024
   - 位置：`plugin-acad26/FoundationGeometryReader.cs`（`issue_count` 原本完整，`issues` 数组与 `issues_truncated` 阈值同步放宽）。
   - 原因：1942 条 issue 的块只能看到前 128 条，缺页原因不可诊断。

3. `query` 空间过滤不再因单个坏块整单失败
   - 位置：`shared/Cad/CadQueryService.cs`（`IntersectsBounds`）。
   - 行为：几何范围不可读（空块定义、代理块、退化几何）或非有限时，该实体从本页排除，查询继续；不再抛 `spatial filter could not read geometric extents for handle ...`。
   - 实测：对 v5 真图（含 `131015/tzblxx`）按全图窗口查询，返回正常（此前必挂）。
   - 代价：被排除实体不再出现在空间查询结果中，仍可按句柄用 `read` 单独读取。这是明确的取舍：宁可少一条，不让整次查询不可用。

## 二、撤销的旧结论（不是缺陷）

- `install` 并不写 `session.json`；同工作区 `start` 报 `Existing session preserved` 是因为该工作区之前起过会话（`session.json` 存在）。正确做法是换新工作区，或 `start --reopen`（已实测可用）。
- `apply --save-to` 只能指向本会话绑定的 work.dwg，交付副本走 `publish-dwg`。BUG-05（改路径后绑定失效）已由该约束消除，不再是开放缺陷。

## 三、仍然存在，且本轮未改（含边界结论）

1. `nested_geometry_coverage` 恒为 `"not_read"`（`shared/Cad/CadEntityProperties.cs`）。属性描述阶段并不知道是否被读取；真实读取状态在 `read` 回执的 `reference_read`。建议下版改为显式指向 `reference_read`，避免误读。
2. `view` 之后 DBMOD 变脏，`stop` 要求先 `save`。属可接受的操作纪律（视图后补一次 save），本轮未改插件侧。
3. 非均匀缩放块内 `Circle/Arc` 跳过（`TransformBy` 不适用）。影响仅限此类块的嵌套几何精度。
4. 大输出经 CLI 回读会被客户端序列化上限截断为 `{truncated, preview, hint}`。这是本地保护，不是数据丢失：完整结果在 `drawings/outputs` 回执里，或按 handle 分页读。
5. 包未签名（`signing: null`）。本机无签名证书，不签。
6. 本机无 AutoCAD 2026，2026 宿主路径无法回归。
7. 不开放任意 Lisp/脚本执行。这是安全边界，不随版本开放。
8. `AutoCAD 2022\Plugins` 下历史版本目录持续累积（每次 install 新建一个 v1-<bundle12>）。建议按"只保留在用版本"清理，属运维动作，需明确点头后执行。
