## 本次解决的实际问题

云岗路总图实战中，块 `B9672` 内三条目标轮廓里有两条读不出来：

1. **嵌套图元没有图层**：`geometry_read.primitives[]` 只有几何，没有 `layer`，无法按“地形图 / 设计线 / 保护范围”判断。
2. **Hatch 边界被整类跳过**：读取器对 `Hatch` 走默认 `Explode()`，直接 `eNotApplicable`；以填充或 Hatch 边界表达的站体轮廓完全不可见。
3. **非均匀缩放块参照被整类跳过**：默认 `Explode()` 抛 `eCannotScaleNonUniformly`，嵌套站体、车辆段等块参照无法展开。
4. **嵌套展开预算被无关块耗尽**：全图块读取固定 4096 节点 / 60000 标量，标题、指北针等先占满预算，目标区域还没轮到。
5. **读取不能按空间窗口裁剪**：没有 `geometry_window`，无法只展开目标区域。

## 代码改动

- `plugin-acad26/FoundationGeometryReader.cs`
  - 每个图元输出 `layer`。
  - `Hatch` 直接读取边界环：`HatchLoop.Polyline`（`BulgeVertexCollection`）转成 `Polyline` 边界图元，带 `boundary_of="Hatch"`、`loop_type`、`closed=true`；关联式边环回退到 `GetAssociatedObjectIdsAt`。
  - `BlockReference` 不再 `Explode()`，改为打开块定义、逐子图元 `Clone()` + `TransformBy(blockReference.BlockTransform)` 展开；子图元先做窗口相交判断再展开。
  - 节点/标量预算提升到 50000 / 300000，并输出真实 limits。
  - 新增 `geometry_window` 过滤：块子图元与叶图元都按 WCS 范围裁剪。
- `shared/Cad/HandleBatchRequest.cs`
  - 新增 `GeometryWindow`，校验 `min_x/min_y/max_x/max_y` 均为数值且 `max>min`；要求单句柄 + `include_geometry=true`。
  - 规范字段白名单加入 `geometry_window`。
- `server/Execution/BoundPluginExecutionGateway.cs`
  - 透传 `geometry_window`，兼容对象与 JSON 字符串两种入参，按原始数值 token 复制，避免 `int/float` 深度比较不一致。
- `server/Tools/QueryTools.cs`
  - `dwg_get_entity_properties` 增加 `geometry_window` JSON 字符串参数。
- `shared/Infrastructure/SchemaValidator.cs`
  - `GetEntityProperties` schema 增加可选 `geometry_window` 对象。
- `shared/Handlers/GetEntityPropertiesHandler.cs`
  - 将 `request.GeometryWindow` 传入读取器。
- `client/foundation.py`
  - `read` 新增 `--geometry-window "min_x,min_y,max_x,max_y"`，校验四值且 `max>min`，以 JSON 字符串提交。
