# 保存字体文件名兼容修复 2026-10-28

本机候选版本1.2.0-beta.3.4，AutoCAD2026／.NET8。

2026-10-16给水样图收尾记录已明确：字体文件名经CAD保存归一化，导致严格符号表读回失败，而选定对象、图层、布局和模型集合一致。它是已知未解决项，不是删除聊天造成。旧有TextStyleSaveEquivalent只覆盖部分方向；本轮实际差异包含旧TTF文件名变空，因此仍失败。

修复只用于单步save：两个方向均允许空值与.ttf文件名归一化，要求非空且完全相同的resolved_font，所有其他文字样式字段相同，BigFont为空。SHX、大字体、字号、字宽、字形属性的变化不放行。新增正反向和拒绝用例。

本轮另发现代理内存分解产生非驻留对象事件，被DrawingRevision误认为源图编辑；仅忽略ObjectId为空的临时对象事件，真实数据库对象变化仍使读取失效。当前须通过原生复测，不以编译通过宣称实战通过。

恢复原保存请求使用tools/SaveFontRecovery，只读复核同一CAD进程、图纸、插件MVID、原请求及序列、原回执哈希。重新读取磁盘与内存的对象、样式、图层、布局及模型清单，并核实文件哈希不变；通过后调用现有的分阶段核验和终结接口，不执行保存、不改原结果、不删除日志、不手工删除围栏。服务端用相同证据校验并同步。失败则保留原状态；未知写入不适用此恢复入口。

本轮原请求恢复已在原会话完成，服务端与原生均passed并释放围栏。最初失败回执保留。私有图纸与回执不随包发布。

代码检查114项、恢复证据契约7项通过；实际原请求磁盘及内存复核通过。新插件后续正常保存、代理读取的原生验证另记录，不把旧进程恢复当作新插件全能力验收。没有修改已发布tag、没有推送GitHub。
