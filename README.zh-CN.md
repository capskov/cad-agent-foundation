**面向连续 CAD Agent 工作流的可靠执行底座。**

让智能体明确绑定图纸，持久记录请求归属与执行状态，在回应不明确时查询原请求，并在写入和保存后核对指定对象。当前实现集成在经过修改、固定来源版本的 [Bimwright DWG MCP](https://github.com/bimwright/dwg-mcp) 宿主中。

维护者：**capskov**。当前工程基线为 **v1.0.0-local**；本次公开源码预览不附可运行二进制包，也不代表所有 AutoCAD 2026 补丁版本均已兼容。

## 为什么开发

项目来自道路土建 CAD 实战：圈边界、做填充、统计数量、安排关联标注，再经过多轮修改、保存和续作。这个过程中，智能体除了需要能用的绘图命令，还需要回答：

- 我操作的究竟是哪张图、哪个实例？
- 这次请求已经执行了吗，还是只是回应丢失？
- 实际对象与预期一致吗，磁盘上的图是否已保存？
- 如果继续尝试，会不会重复创建或重复修改？
- 目前是已核验、失败，还是仍无法确认，应该怎样安全停下？

这也是最初的项目思路：在现成 CAD 执行能力上建立可追踪、可核验的执行约束，支持更长的真实工程工作流。工程范围和排布规则保留在独立 Skill；底座维护身份、请求、状态、写入与读回之间的约束。

增加持久记录和核验会带来额外开销。目前没有对照数据证明比其他项目更快、更省算力或更高效，也不宣称事务、去重、状态机等思想由本项目独创。

## 当前侧重点

1. 精确图纸绑定：核对进程启动身份、图纸路径、文档/数据库会话和实际加载插件版本。
2. 请求不失忆：两端持久记录归属，原服务重启后在同一 CAD 会话中查询原请求；未知写入不自动重放。
3. 操作有边界：原生图层、线、圆、多段线、文字、关联填充、普通 LEADER/MTEXT/黄色实心点组。
4. 修改有旧值保护：使用刚读到的对象摘要，关联组成员完整才允许相应文字更新、移动和归档。
5. 保存有核对：整图保存后独立从磁盘读回指定对象，同时核对模型句柄集合和图层；只确认检查范围内的事实。
6. 一个本地入口：CLI 与 MCP 使用同一服务和账本，版本化安装、独立工作副本、状态和停止流程一致。

“侧重点”不等于其他项目没有这些机制。我们公开的是这套受限操作流程中已实现和实测的约束；其他项目的优点、后端区别和采用情况放在[背景与相关项目](docs/BACKGROUND-AND-RELATED-PROJECTS.md)，不在首页做优劣排名。

## 运行与验收范围

当前目标是 Windows x64 的 AutoCAD 2026，向二维模型空间写入有界计划。坐标、长度和标注尺寸按图纸单位解释；WCS 表示 CAD 坐标参照，并不规定米制，也不等于高斯投影。底座不进行地图投影或单位换算。

**当前首版的写入接口仍限制米制**：计划必须声明 `units: metres`，图纸单位须为米，或明确约定为米的无单位图。毫米等其他单位尚未开放、未验证。米制是当前实现边界，不能据此把底座用途限定为道路。默认关闭写入，打开时仍只暴露有限计划入口。已在两份不同来源图纸的工作副本中完成创建、读取、关联文字修改、完整组移动、归档、保存、关闭重开和读回；CLI/MCP 与本地安装包也有验收记录。

这些证据不等于任意工程图、任何 AutoCAD 2026 补丁或每个 MCP 客户端均已验证。软件发现的身份未知、提交未知和核验未知必须如实保留，不能统一写成成功，也不能把提交后核验失败当作已经回滚。

首个目标选择 AutoCAD 2026，是因为它匹配实际工作环境及采用的 Bimwright 原生插件路线，便于围绕一个宿主建立安装和执行证据。当前本地基线使用 .NET 8、文档锁和事务；2025 也使用 .NET 8，较早版本也有自动化接口，MCP 由桥接服务提供。[选择依据](docs/WHY-AUTOCAD-2026.md)

实测宿主记录为 R25.1.74.0.0；2026.1.2 引入 .NET 10 更新后的兼容性尚未验证。[官方运行时更新](https://blog.autodesk.io/autodesk-desktop-products-2025-2026-net-10-updates/)

未开放：原生尺寸标注 DIMENSION、多重引线 MLEADER、复杂旧填充修复、任意多段线形状编辑、跨图复制、代理语义、布局/出图、自动工程判断、未知写入自动解锁。CLI 的保存作用于整张工作图，而不是仅保存所列对象。

## 按任务选择组件

| 任务 | 所需组件 | 版本与限制 |
| --- | --- | --- |
| 已支持的基础 CAD 操作 | 仅 `cad-agent-foundation` | 本地基线 `v1.0.0-local`；公开源码预览 `v1.0.0-rc.1`，不附可运行二进制资产。有界二维操作，当前写入限米制，仅有记录的 Windows／AutoCAD 2026 宿主实测。无需两个 Skill。 |
| 本项目的引线标注样式与排布 | 底座 + `cad-callout-pair-layout` | 标注规则 v0.3，公开导出待完成。默认与验证来自米制道路图；完整样式、排布尚未通过底座首版单独执行验收，写入前须核对后端覆盖。 |
| 本项目的病害／拆除标注工作流 | 底座 + `cad-distress-annotation` + `cad-callout-pair-layout` | 病害拆除规则快照尚无独立公开版本。需要工程依据、分类规则及标注规则；完整流程仍需首版配置之外的能力，尚未验证仅靠这三个组件即可全部复现。 |

基础操作不需要两个 Skill；Skill 规则并未内置到底座，安装它们也不会补出缺少的原生操作。底座源码公开；两个 Skill 仓库仍拟建、尚未公开。[安装入口、版本与 Agent 检查](docs/COMPONENTS-AND-INSTALLATION.zh-CN.md)。

## 入门、Skill 和来源

已有[匿名道路拆除案例](examples/road-demolition/README.zh-CN.md)：标注前后各四页，附主要工程量、路面工程量和路口桩号依据表。这展示配套Skill的历史实战效果，不作为全流程仅依靠底座首版完成的证据。

使用入口为 `foundation.cmd`，安装和调用详见[快速入门](docs/QUICKSTART.zh-CN.md)。公开下载链接将在资产、隐私与许可审查通过后补充，不直接把当前本地 ZIP 当作公开包。

底座负责“在指定图纸上执行什么操作，以及执行结果是否有证据”；Skill 负责“根据专业任务，应该画什么、怎样排布与检查”。底座本身不判断植物品种、病害处理范围或工程量含义。

拟独立发布 `cad-callout-pair-layout` 与 `cad-distress-annotation`。前者管理引线文字、圆点和有限排布，后者管理道路病害/拆除的证据、范围与工程规则。引线标注这种方法也可用于园林植物等分类说明；现有 Skill 的验收背景和默认规则仍来自米制道路图，其他专业和毫米图需要适配尺寸、样式与排布规则，尚未验证。两项 Skill 保留当前节点，尚未确认所有流程都能仅用 Foundation v1.0 完成，不能写成已完全迁移。

其他 MCP、COM 或工具可以另行使用；**只有经过当前底座入口的受支持操作，才进入它的请求记录、执行约束和核验流程**。它不是自动包住任意外部工具的保护层。外部写入不自动共享事务、请求身份或写入阻隔，不能以切换工具绕过未知写入状态。详见[底座、Skill 与外部工具的关系](docs/FOUNDATION-SKILLS-AND-OTHER-TOOLS.md)。

研究过程在首页只保留简述：先按真实工程任务考察现成 CAD MCP/后端，再以固定版本 Bimwright 原生宿主集成执行约束，最后对受限流程做 CAD 写入、读回与保存重开核验。具体采用、参考与评测关系放在[背景与相关项目](docs/BACKGROUND-AND-RELATED-PROJECTS.md)，感谢与许可按实际来源列明。

Bimwright 是当前集成宿主，来源固定在 [4d0f756](https://github.com/bimwright/dwg-mcp/commit/4d0f75646631186612af926944d7e33affc4757d)。公开源码采用 Apache-2.0，保留原第三方许可和署名；首个公开源码预览为 `v1.0.0-rc.1`，二进制资产仍待自身审核和验证。字体与依赖不是自动归入代码许可；AutoCAD/SDK不打包，未确定授权的 HZTXT 字体不随公开版分发。项目独立维护，未获 Autodesk 或上游作者背书。
