# Contributing

Human and AI-assisted contributions are welcome. Explain the user problem, the supported operation affected and the evidence that the change works. The maintainer reviews changes before merging or publishing; an agent's assertion of success is not independent CAD verification.

Keep changes focused. Reuse the existing execution design. Never bypass drawing identity, fresh old-value checks, complete associations or unknown-write fences. Do not revive closed H1/J10/arc-hatch investigations without a new concrete requirement.

Use disposable drawing copies. Supply synthetic or cleared anonymized fixtures and avoid private drawings, precise project locations, credentials, machine paths and proprietary SDK binaries. Test only the affected behavior and required installation flow. Distinguish offline tests, native CAD readback and saved-file evidence.

Document exact host/runtime versions and limits. Adding a native primitive requires its input boundaries and verification contract; adding a Skill requires its domain rules and tested backend combinations. Unit changes must account for sizes and tolerances rather than changing a declaration alone.

Preserve third-party attribution and licenses. Do not upload fonts or other assets with unclear redistribution permission. Contributions must be material that the contributor is authorized to submit under the applicable license.
